# @toolpath/catalog-data

The tool catalog's data contract, the pure transforms that build it, and the
sample dataset the application ships with.

## The document

`Catalog` is one flat list of tools, the families they came from, and a
precomputed facet index. **Lengths are millimetres and angles are degrees**, the
same basis the Toolpath API states, so an inch-published tool and a metric one
compare without the reader knowing which is which. `unitSystem` records how the
vendor published a family — a fact about the tool, not the unit anything is
stored in.

Geometry keeps `@toolpath/tool-scraper`'s canonical field names, with each
one's ISO 13399 code recorded beside it. Seven are the standard's own; `SFDM`
and the two shoulder fields are Autodesk's names, kept because that is what a
downstream consumer recognises. Renaming them here would mean a translation
table, and a translation table is where an `SFDM` becomes a `DC` in one
direction and nobody notices.

## Ingesting a scrape

```sh
pnpm --filter @toolpath/catalog-data ingest ../path/to/scrape.json catalog.json
```

The input is **records**, not vendor CSVs. A scraped CSV deliberately keeps that
vendor's own column labels, and those collide with ISO 13399 while meaning
something else — Kennametal's `D1` is the cutting diameter where the standard's
`D1` is a fixing hole. The scraper's rule is that only a vendor's own adapter
reads that vendor's CSV, and that a `ToolRecord` is where it hands off; `Scrape`
in `src/ingest.ts` is that record set as a document.

The ingest converts inch families to millimetres, reorders material groups onto
ISO 513's sequence, validates that guids were minted by the scraper, and
**prints everything it left out**. A silent ingest is how a catalog ends up
missing a dimension nobody notices for a month.

## The sample dataset

`fixtures/sample-catalog.json` is generated by
`scripts/build-sample-catalog.mjs` through the same `buildCatalog` a real
ingest uses, and `sample-catalog.test.ts` fails if the committed file and the
generator disagree. Nine plausible tools that exercise every branch the UI has.
**They are not a vendor's numbers**, and no scraped vendor data belongs in this
repository.
